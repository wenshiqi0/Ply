# RFC 0005: TUI 插件与终端权限审批

状态：已实现。当前有效契约以 [SPEC.md](../../SPEC.md) 为准；本文件保留方案细节、边界与操作示例。

## 问题与决策

终端交互需要可见输入框、Markdown 回复与真实用户审批；TUI 通过 agent 对话，不自行收窄 agent 工具集。

`ply tui` 启动内置 `tui` 插件在 `ply:commands` 注册的入口，在当前前台终端与 agent 交互、查看结果和用量，并批准或拒绝模型发起的工具调用。TUI 通过 `import plugins from "ply:plugins"` 获取目录，只调用 `plugins.agent({ prompt })`，不直接调用其他业务工具，也不设置 agent 的工具白名单、模型轮数或委派参数。界面逻辑是 TS 插件；原生 `ply:terminal` 提供 `/dev/tty` 输入、屏幕绘制和终端恢复，不启动外部 Node。

```bash
cargo build -p ply-cli --locked --offline
./target/debug/ply tui --record /tmp/ply-tui.jsonl

# 跳过人工确认；默认不启用
./target/debug/ply tui --bypass

# 可选：直接提供第一个任务
./target/debug/ply tui "只读分析当前项目，先列出目录"

# 叠加 Jev 风险评估，自动审查读取宿主 TYPESAFE_API_KEY
./target/debug/ply tui --jev

# 切换模型，读取宿主 MIMO_API_KEY
./target/debug/ply tui --model mimo-v2.6-pro
```

普通任务使用宿主 `DEEPSEEK_API_KEY`，默认 DeepSeek。`--mount`、`--context-*`、`--agent-max-children`、`--agent-report-section` 和 `--plugin` 等通用选项也可使用。默认挂载当前工作目录。只读磁盘可以显式使用 `--mount disk:PATH:ro`。

## 输入与结果

输入区固定在屏幕底部，有独立边框、“输入消息”标签、占位提示和真实终端光标。输入自动换行，最多显示六行，更多内容跟随光标滚动。中文、组合字符和 emoji 按字素编辑，光标按终端单元格定位。正常输入只重画变化的行，切换审批或调整窗口大小时才清屏重绘。

| 输入 | 行为 |
|---|---|
| 普通文字 + Enter | 启动一个 agent 任务，结束后显示报告与自身子树的 token 用量、缓存命中率 |
| `/help` | 查看快捷键与命令 |
| `/clear` | 清除界面保留的任务文本 |
| `/quit` 或 `/exit` | 空闲时退出 |
| Alt+Enter / Ctrl+J | 插入换行；能报告扩展按键的终端也支持 Shift+Enter |
| 多行粘贴 | 保留换行和缩进；粘贴内容不会自动发送 |
| ←→ / Backspace / Delete | 按字素移动、删除，不拆开中文或组合 emoji |
| Home/End、Ctrl+A/E | 移到当前逻辑行首或行末 |
| ↑↓ / Ctrl+P/N | 在输入的视觉行间移动；首行/末行切换已发送消息历史 |
| Ctrl+U/K/W | 删除到行首、行末、前一个空白分隔词 |
| PageUp/PageDown | 翻阅结果，保留输入焦点 |
| Ctrl+L | 重绘屏幕，保留输入与历史 |
| Ctrl-C | 退出；任务运行中会取消当前任务及其等待中的子 fiber |
| Ctrl-D | 输入为空时退出；有文本时删除光标后的字素 |

任务执行中有动态状态与耗时，可继续编辑下一条草稿；此时 Enter 只提示保留草稿，不创建另一个 agent。执行完成后再按 Enter 才发送。审批有单独的选择区，草稿保留，粘贴与残留按键不会批准操作。

每个普通任务是独立的 agent 对话，不把上个任务的报告自动放进新模型上下文。任务完成后显示报告，当前没有模型文本逐 token 流式展示。单次输入上限 65536 字符，超限拒绝提交；界面保留最近 200 条文本记录，需要完整轨迹时使用 `--record`。

### 回复排版

Ply 的回复通过 CommonMark 解析后显示，支持标题、粗体、斜体、删除线、行内代码、嵌套/有序列表、任务列表、引用、带语言标签的代码框、链接和表格。普通 Markdown 标记不直接打印；代码块中的星号、井号和缩进保持为代码内容。

表格按终端单元格宽度分配列宽并换行，过窄时改为字段列表。中文、组合 emoji 和窗口缩放继续按终端宽度排版。链接显示文字与目标地址，图片显示说明与地址；不下载资源、不执行 HTML。ANSI/OSC 和双向控制字符仍按文本转义。

只有 assistant 回复使用 Markdown 排版；用户输入、审批参数和原始代码预览按字面显示。模型原始 text 与 JSONL 轨迹保持 Markdown，不影响报告完整性校验、上下文或 token 用量。解析超出大小/深度/节点限额时回退到纯文本。

用量小计来自已返回的 agent `total_usage`，不重复累加各级子 agent。启用 Jev 后，其检查用量也按原有子树口径汇总。缺失缓存分项显示“未知”，不填 0。失败任务用量以 JSONL 中的 model_call / agent_usage 为准，界面标记会话小计不完整。

## 权限范围

工具目录与执行审批分别由 agent 和 [approval 插件](0003-approval.md) 管理：

`--bypass` 是 CLI 宿主的显式开关，只跳过人工审批。界面标题和状态区会显示 BYPASS。工具授权、子 agent 数量/代数、只读挂载、参数校验和普通 hook 的硬拒绝继续生效；它不会让内部 sh 调用未知宿主命令。模型参数不能开启该模式。

`--bypass --jev` 仍执行并记录 Jev 评估；需要确认的建议按宿主 bypass 策略授权，不弹审批界面。每次跳过写入 `approval_bypassed`，不伪造用户/审批服务响应，也不计入人工批准次数。

- 默认主 agent 拿到 `agent/bash/create/edit/memory/read/remove` 七个工具；默认子 agent 移除 `agent` 与 `memory`，保留另外五个并读取继承的记忆快照。显式收窄工具集仍属于 agent 的能力，TUI 不额外传 `allowed_tools`。技能自动发现与插件参数 见 [Skills](0006-skills.md)。
- CLI 宿主默认选择 `ask` 策略：模型调用 read/create/edit/remove、其他已注册工具以及 agent 委派，均在 agent 的执行层先审批；bash 在自身的执行前检查和 Jev 评估后审批一次。`--bypass` 选择上述显式跳过策略。没有 pwd 特例。
- read 获准前不会启动文件工具或读取内容；create/edit 展示已提交的内容、替换参数；remove 展示路径与递归参数。预览不会提前读取目标文件。批准绑定原始参数，不能通过响应改写调用。
- 默认允许一代子 agent，每个 agent 最多累计创建两个直属子 agent；子级不能继续委派。`--agent-max-children` 可调整数量，模型轮数仍不设上限。这些限制由 agent 自己的默认策略处理。
- 审批显示原始调用参数或命令、工作目录和已知风险结果；请求 ID、fiber 保留在运行轨迹中。长请求可滚动，到达末页后才启用批准；模型输出和粘贴内容不能当作批准输入。
- `y` 只批准当前操作一次；`n` / Enter / Esc 拒绝。用户输入任务启动主 agent，无需重复批准；模型进一步委派子 agent 属于需审批的工具调用。
- 并发请求逐个显示和关联，同一 agent 的请求有独立 ID；上一请求剩余按键不会批准下一请求。取消、超时后移除过期审批，不启动待审工具。
- 审批等待默认五分钟，由 `PLY_APPROVAL_TIMEOUT_MS` 配置；不消耗 sh 的执行期限。超时仍返回待审批状态，没有跨进程自动恢复或旧命令自动重放。

当前终端用户是批准主体，不另做账户登录。TUI 必须能打开真实的、属于前台进程组的 `/dev/tty`；管道 stdin、MCP 消息或模型输出都不作为批准来源。没有终端则明确失败，不降级为自动批准。

## 插件接入

`tui` 是 opt-in 内置插件。`ply tui` 自动加载 `approval` 和 `tui`，宿主在 `KernelConfig.env` 中选择 `PLY_APPROVAL_MODE=ask`，显式 `--bypass` 则选择 bypass。仅加载 TUI 插件不会打开界面或选择审批策略。TUI 只展示实际策略与请求，不自行修改工具权限。

`onLoad` 订阅 `approval.request` 和 `approval.toolRequest`，并通过 `commands.register({ name:"tui", handler:onHandle })` 注册入口；回调复用已有界面实现。TUI 不订阅工具的 beforeExecute 来定义策略，也不调用 `context.registerTool`。Rust 嵌入时由宿主选择审批模式、加载插件、等待 ready，再 `Kernel::run_command("tui", input)`；在 MCP 等环境应使用相应的宿主适配器。注册接口见 [命令文档](0004-commands.md)。

`ply:terminal` 的 session 由打开它的 fiber 所有，原生层在成功、失败或取消时回收。正常路径也在 finally 关闭；即使 JS 清理失败，宿主仍会恢复 termios、光标、粘贴模式及原屏幕。UI 不解释命令/模型文本中的 ANSI、OSC、双向控制字符；小于 40×10 的终端不能批准。

真实 PTY 验收见 [crates/ply-cli/tests/tui.rs](../../crates/ply-cli/tests/tui.rs)。测试只使用本地 fixture 与临时目录，不调用供应商，也不授权任何测试目录之外的命令。

Markdown 使用内嵌 `ply:markdown` 模块：Rust 解析 CommonMark，JSC 负责终端排版，再由 `ply:terminal` 渲染安全的文本 span；运行时不依赖外部 Node。解析与窄窗口验收见 [Markdown 集成测试](../../crates/ply-kernel/tests/markdown.rs)。
