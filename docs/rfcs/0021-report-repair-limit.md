# RFC 0021: 报告章节规范化与有限修复

状态：已实现
关联规范：SPEC-AGENT

## 问题与证据

`report_sections` 接受任意非空单行标题，调用方会传入 `## Findings`。报告解析先移除 Markdown 标记，而必填标题未移除，同一标题被判为缺失。2026-11-02 的本地复现中，四章齐全的报告被判定缺少全部四章。无 `max_turns` 的任务可持续重写，直到宿主超时。

## 方案

比较标题时，对要求和报告使用相同的 ATX 标题及编号规范化，继续要求章节存在且非空。每个任务累计最多拒绝三份报告，允许前两次拒绝后在原 agent 内修复；第三次明确失败，包含稳定原因。恢复保留计数，耗尽后在模型调用前失败，不通过恢复重置自动修复预算。

## 兼容范围

保留 CLI、插件输入、报告结果和恢复格式 4。普通任务工具轮数仍默认不限。已有 Markdown 标题要求直接按统一规则匹配，原要求文本保留在状态中。真实模型调用不用于自动验收。

## 验收

用内核模型 fixture 验证中文及带编号/Markdown 标记的必填章节一次通过，缺章节/空章节继续被拒绝，永久无效报告只调用模型三次；验证恢复耗尽记录不再调用模型，已有修复与恢复场景继续通过。运行 npm 静态检查及相关 Rust 内核/CLI 测试。

## 规范同步

更新 SPEC-AGENT、agent 使用说明和 RFC 索引。复用既有 `rejected_reports` 字段，不新增恢复字段或 SDK 输入。

验证记录：2026-11-02，本机 Node 24.14.0 的 `npm ci --ignore-scripts` 和 `npm run check` 通过；内核 agent 集成回归、5 项 ACP 和 14 项真实 PTY 测试通过，均使用 fixture / 本地服务，无供应商调用。
